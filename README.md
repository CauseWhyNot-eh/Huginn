# Huginn

Vague idea in. Buildable spec out.

Huginn takes a vague app, site, skill, or workflow idea and returns a spec with features, build steps, and inner working. It does not write code or validate markets.

## How a run goes

1. **Record** — your raw idea, saved as-is.
2. **Gap-check** — at most 3 sharp questions (user, scope, mode), with guesses.
3. **Options** — 2–3 directions with different scopes.
4. **Sharpen** — picked direction expanded into features (V1 vs later), build steps, user flow plus system flow, and open unknowns.
5. **Lock** — spec version plus one next action.
6. **Learn** — only writes back on a real signal (a correction, a repeated point, a direct ask). Quiet runs leave the files untouched.

## Layout

- `SKILL.md` — the workflow core.
- `prefs.md` — style layer (plain words, short paragraphs, tables).
- `learnings.md` — lessons learned from real runs. Starts empty.
- `templates/` — spec shape plus a worked example.
